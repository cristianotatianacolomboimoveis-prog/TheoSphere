# ADR — MCP 2026-07-28 Tasks and HTTP production path

**Date:** 2026-09-18  
**Status:** Accepted for `feat/theosearch-evidence-linguistics`

## Decision

TheoSphere implements MCP `2026-07-28` as a stateless HTTP protocol while retaining the handshake-era `2025-11-25` and `2025-06-18` compatibility path.

Modern requests are self-describing and are validated per request. The HTTP controller requires `MCP-Protocol-Version`, `Mcp-Method`, and for task/tool routing `Mcp-Name`, plus the protocol metadata in `_meta`. Modern responses expose `resultType` and cache hints where applicable.

The `io.modelcontextprotocol/tasks` extension is implemented for `tools/call`. Task handles are durably persisted before the handle is returned; clients retrieve state with `tasks/get`, may provide `inputResponses` with `tasks/update`, and request cancellation with `tasks/cancel`. The implementation intentionally does not expose `tasks/list`, because the 2026-07-28 extension does not define it.

## Verification basis

The official Tasks specification (2026-07-28) requires:

- `resultType: "task"` for `CreateTaskResult`.
- `tasks/get`, `tasks/update`, and `tasks/cancel`.
- `resultType: "complete"` for task polling/update/cancel results.
- durable task creation before returning a task handle.
- `-32602` for invalid/nonexistent task IDs.
- `-32021` when the required Tasks capability is missing.
- `Mcp-Name` equal to `taskId` for task routing over Streamable HTTP.

Reference: https://tasks.extensions.modelcontextprotocol.io/specification/draft/tasks

The core 2026-07-28 release documentation confirms the stateless lifecycle, removal of `initialize`/`Mcp-Session-Id` for modern clients, `server/discover`, header-based routing, and cache hints.

Reference: https://blog.modelcontextprotocol.io/posts/2026-07-28/

## Production-test decision

The backend CI gate includes an HTTP E2E smoke that exercises:

1. modern `server/discover`;
2. modern synchronous `tools/call` research;
3. asynchronous task creation;
4. polling to completed task state;
5. `tools/list` cache hints;
6. legacy `initialize` compatibility.

The E2E suite additionally covers task cancellation and invalid task handles.

No paid model/API calls are required by these tests; CI uses empty external AI credentials and deterministic/local test behavior.

## Operational blockers

The code-level CI for commit `30a18fed` was green, including backend, frontend, Prisma drift, Security Audit, and the MCP HTTP E2E smoke. External deployment checks remain independent of code correctness: the Cloudflare Workers staging integration has reported failed builds, and Vercel has previously reported build-rate limiting. These must not be represented as application test failures.

## Safety boundary

`main` is not merged or modified by this ADR. The feature branch remains the integration and validation surface until external deployment checks and human release decisions are resolved.
